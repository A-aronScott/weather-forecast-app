# Weather Forecast App – Project Instructions

## 1. Project Overview

Build a responsive weather forecast application using React, JavaScript and CSS.

The application will allow users to search for weather conditions by city and view current weather information and a five-day forecast.

This is a school project. Code should be understandable, maintainable and appropriate for a  software development student.

## 2. Technology

- React
- Vite
- JavaScript (ES6+)
- HTML5 and CSS3
- Bootstrap where appropriate
- OpenWeatherMap API
- Playwright for end-to-end testing
- Git and GitHub for version control

Do not introduce additional libraries or frameworks without discussing them first.

## 3. Development Workflow

- Use Plan mode before significant development tasks.
- Inspect existing code before proposing changes.
- Present a concise implementation plan.
- Wait for approval before implementing the plan.
- Work on one manageable task at a time.
- Avoid unnecessary changes to existing files.
- Explain important decisions and unfamiliar code.
- Do not rewrite working code unnecessarily.

## 4. Permissions and Safety

- Read project files when necessary.
- Never assume permission to modify files.
- Never assume permission to execute terminal commands.
- Request approval before installing packages.
- Request approval before deleting or replacing files.
- Request approval before performing Git operations.
- Never expose, commit or share API keys or other secrets.
- Never modify project configuration without approval.

Actual permissions are controlled through Cline settings, not this document.

## 5. Token Efficiency

- Keep responses concise and relevant.
- Avoid repeating information already established.
- Read only the files relevant to the current task.
- Avoid unnecessary explanations and repeated analysis.
- Do not use subagents unless specifically approved.
- Summarize completed work briefly.

## 6. Code Quality

- Prefer simple, readable solutions.
- Use meaningful variable and function names.
- Keep components small and focused.
- Avoid unnecessary complexity and duplication.
- Follow established project conventions.
- Explain unfamiliar concepts rather than hiding their complexity.

## 7. Responsive Design

The application must work on:

- Desktop computers
- Tablets
- Mobile phones

Use responsive layouts and test different screen sizes throughout development.

## 8. Testing

Use Playwright for browser-based end-to-end testing.

Test important functionality, including:

- Application loading
- City searches
- Weather information
- Forecast display
- Error handling
- Responsive layouts

Do not claim that functionality works without testing it.

## 9. Git and GitHub

- Make regular, meaningful commits.
- Commit after completing and testing manageable development tasks.
- Use descriptive commit messages.
- Review changes before committing.
- Push completed commits to GitHub regularly.
- Use feature branches when appropriate.
- Never rewrite Git history or force-push without explicit approval.

I am still getting better ar React, JavaScript, APIs, testing and AI-assisted development.

Prioritize understanding over speed.

Explain important implementation decisions, identify potential problems and encourage me to review generated code.
